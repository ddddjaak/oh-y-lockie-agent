## 1. 版本背景

v1.2.0 是自 v1.0.0 插件重构（移除 command 层、agent 定义收归代码、自然语言路由）后的第一个功能修复大版本。

在使用过程中暴露出的核心问题：**skill 路由指令被运行时忽略、模型解析静默降级、安装/卸载不完整**。本版本逐一修复，并补齐了 CI 与测试覆盖，确保插件在 Linux/macOS/Windows 三平台表现一致。

## 3. 功能与修复明细

### 3.1 Skill 路由可靠性（核心修复）

- **[修复] 移除路由指令的 `ignored` 标记**
  此前注入的 skill 路由指令带有 `ignored` 标记，会被运行时排除出模型上下文，导致「自然语言触发 skill」功能实际不生效。已移除，指令现正常进入模型上下文。

- **[新增] `lockie_load_skill` 工具**
  从插件包内直接加载 `SKILL.md` 全文（不依赖原生 skill 发现路径）。原生 `skill` 工具只扫描 `.opencode/skills`、`~/.config/opencode/skills`、`.claude/skills`、`.agents/skills`，插件随附的 63 个技能可能不被发现。路由指令现指向本工具，加载可靠性不再依赖发现路径。

- **[改进] 路由表注入双通道**
  路由表同时注入每个 agent prompt（config hook 通道）+ `experimental.chat.system.transform`（部分运行时可能丢弃，agent prompt 兜底），消除单通道失效风险。

### 3.2 模型解析降级

- **[修复] probe 过滤非对话模型**
  模型探测现在过滤 embedding / whisper / image 等非对话模型，避免 agent 被分配到无法对话的模型上。

- **[改进] 降级显式警告**
  `fallback-any`（默认模型不可用，回退任意可用模型）与 override 不可用时，从静默 log 改为 `warn` + `lockie_status` 工具显式列出警告，用户可感知模型降级并据此配置 `oh-y-lockie-agent.jsonc`。

### 3.3 安装 / 卸载 / CLI

- **[新增] CLI bin**
  `package.json` 补齐 `bin`（`oh-y-lockie-agent` → `scripts/setup-mcp.mjs`），`npx oh-y-lockie-agent setup-mcp` 真正可用。

- **[新增] postinstall 自动复制 skills**
  `npm install` 后自动把 63 个 skill 复制到 `~/.config/opencode/skills/`（仅补缺失、不覆盖用户已有，manifest 记录用于安全卸载）。

- **[新增] preuninstall 安全清理**
  `npm uninstall` 前按 manifest + sha256 只清理**未改动**的 skill 目录（用户改过的保留），含路径越界防护。

### 3.4 文档

- README / AGENTS.md 同步至 v1.2.0：模块树、初始化流程、安装/卸载说明。
- `references/orchestration-patterns.md` 标注为历史文档（command 层已移除）。
- `package.json` description 修正为「63 skill」。

### 3.5 工程

- **[新增] GitHub Actions CI**（`.github/workflows/ci.yml`）：编译 + 测试门禁。
- 测试覆盖 162 → 174：新增 `loadSkillContent`、非对话模型过滤、路由指令不带 `ignored` 断言。

## 5. 升级说明

```bash
# 全新安装
npm install oh-y-lockie-agent

# 已有安装升级
npm update oh-y-lockie-agent

# 手动配置 MCP（如 postinstall 未执行）
npx oh-y-lockie-agent setup-mcp
```

安装后验证：

```bash
# 1. 检查插件健康状态（16 个 agent、模型解析、MCP、skill 索引）
opencode   # 会话内运行 lockie_status 工具

# 2. 验证 skill 路由触发（自然语言即可，无需 slash 命令）
#    例：「帮我做引脚复用分配」→ 应路由到 pinmux skill
```
